Every appointment request stays visible until the confirmation call actually happens

A BBB complaint from October 2025 describes a customer requesting an appointment that never got booked, because a system error with the company's virtual assistant blocked the confirmation call and same-day service was no longer available by the time anyone noticed. A separate complaint from September 2024 describes a service that was never completed despite repeated callback requests, and one from June 2024 describes rescheduling delays during a heat wave. Budget already runs on HouseCallPro, so this is not a "need another scheduler" problem, it is a "the confirmation and reminder step does not reliably close the loop when call volume spikes" problem. This example shows a small tool that sits next to HouseCallPro: it holds every request open, with a due-by clock, until someone marks it confirmed, and gives a customer a way to check their own status without calling in.

How this gets built for real

The reference code can come straight from HouseCallPro. A real build reads the job or request ID Budget's system already assigns, instead of asking a customer to remember a new code.
This does not replace HouseCallPro or the virtual assistant. It sits next to them and tracks one specific thing: has this request been confirmed with the customer, and if not, how overdue is that confirmation.
The overdue clock is the actual fix for the BBB pattern. The October 2025 complaint happened because a blocked confirmation call had no backstop. A real build can text or page the on-call scheduler the moment a request crosses overdue, so a same-day window never quietly closes unnoticed.
The customer view shows only customer-safe wording. Internal notes typed in the office view never appear on the lookup page.
