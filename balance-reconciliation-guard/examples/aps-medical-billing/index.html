A statement queue that catches a balance mismatch before it reaches a patient.

APS Medical Billing runs pathology, laboratory, and radiology billing and payor credentialing for over 190 practices nationwide from a single Toledo, Ohio location, work it has done since 1963. Public complaints on file describe a specific, recurring pattern: a balance the office shows as resolved reappearing on a later statement, and duplicate statements after a new client practice's billing was transitioned onto APS's own system. This example applies the reconciliation-guard template to that exact pattern, using illustrative accounts, not any real patient's record.

Where each check comes from

Phantom-balance hold (statement about to bill a balance the payment ledger already shows paid) directly matches the pattern described in public BBB complaints against APS: a balance confirmed "adjusted to $0" reappearing weeks later at its original amount.
Duplicate-across-systems hold matches a specific documented incident: duplicate billing appeared after APS onboarded a new client practice mid-transition, generating parallel statements from the practice's prior system and APS's own system for the same account.
EOB-pending hold and the stale-statement check are the general form of the same root cause, a statement generated from one system's snapshot without checking whether another source of truth has since moved.

How this gets built for real

This is a checkpoint, not a platform replacement. It sits between whatever generates a statement today and the mail step, reading the billing balance, payment ledger, and 835 remittance data APS already has, not a migration to a new RCM platform.
Holding is conservative on purpose. A false hold costs a billing rep a few minutes reviewing it. A false send is the complaint pattern already on the public record, so the tool errs toward holding when sources disagree.
A held statement only releases on a person's decision. The tool flags the mismatch, billing staff still confirm it is actually resolved before anything mails.
