A lost impression gets caught before a customer has to notice it first

A mail-order lab that works from physical impression kits has one blind spot every purely digital order-tracking tool misses: the kit itself can go missing in transit, or sit untouched at the lab, with nothing automatic to notice. This page shows one small, working tool for that gap: every kit gets logged the moment it should have arrived, moves through received, in production, quality check and shipped, and a kit that never gets logged as received by its expected date, or sits too long in one stage, flags itself into an internal queue automatically instead of waiting for an angry email.

Everything below is fictional. When this gets built for a real business, the intake view is what lab staff use to log each kit and advance it through production, the flagged queue mirrors the same data filtered to what actually needs attention, and the customer reference code is whatever the order system already hands out, not a new code to invent.

How this gets built for real

The flag thresholds are adjustable. A real build sets the overdue-days and stalled-days triggers to match how long each stage genuinely takes for that business, not this demo's defaults.
This tracks the physical kit's stage, not the checkout order. It sits alongside whatever already handles payment and shipping labels, and only tracks whether the physical sample keeps moving once it should have arrived.
The reference code is whatever the order system already uses. A real build reads from an existing order number instead of inventing a new one for the customer to remember.
The customer view shows only customer-safe wording. Internal notes and flag reasons typed in the intake and flagged views never appear on the lookup page.
